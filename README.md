# 招标公告核对助手

采购代理人需要核对两类问题：

1. **招标延期核对**：按项目编号归并原公告、更正公告与延期公告，计算当前有效的投标截止时间；
2. **静默改写核查**：发现网站在**同一个详情 URL** 上直接改写原公告文字，却没有另行发布更正公告的情况。

应用会输入公告列表页地址，沿同站点“下一页”抓取详情页。所有链接只跟随与入口同站点
（协议 + 主机 + 端口一致）的地址，并限制列表页、详情页数量和单请求超时。

## 静默改写核查

入口：<http://localhost:8000/rewrites>（也可在首页点击“核查静默改写”）。

处理规则：

| 环节 | 规则 |
| --- | --- |
| 核查范围 | 按**列表入口 URL** 隔离，不同列表入口各有一份 SQLite 基线，互不干扰 |
| 公告识别 | 以**详情 URL** 作为公告身份；同一 URL 前后出现才进入比较 |
| 比对内容 | 公告字段表（项目编号、公告类型、发布时间、截止时间等）与正文区的可见文字 |
| 空白处理 | 忽略缩进、换行、单元格内多余空格等纯排版空白；脚本、样式、导航和明确隐藏元素不计入 |
| 首次完整采集 | 建立 SQLite 基线，不报告改写 |
| 后续完整采集 | 仅比较前后两次完整采集都存在的公告；展示变动前后文字与来源链接 |
| 基线更新 | 完整采集后用本次结果整体替换该入口的基线（新增公告入基线，消失公告移出） |

### 本次采集“不完整”的情形

以下任一情况发生时，页面会明确标注**本次采集不完整**：

- 列表分页读取失败，或“下一页”无法继续跟随；
- 已识别出的公告详情页读取失败；
- 详情页解析失败（例如详情页缺少项目编号）；
- 达到列表页上限（10 页）或详情页上限（100 条），仍有未读取内容。

此时：

- **不进行改写比对**，也不会给出“未变化”的结论；
- **不覆盖已有基线**，原有基线保留；
- 若从未建立基线，本次不完整采集也不会创建基线。

### SQLite 持久化

- 默认数据库：`webapp/data/snapshots.sqlite3`；
- 环境变量 `SNAPSHOT_DB_PATH` 可指定其他位置；
- Docker Compose 已挂载命名卷 `baseline-data` 到 `/data`，并设置
  `SNAPSHOT_DB_PATH=/data/snapshots.sqlite3`，容器重建后基线仍保留。

## 招标延期核对

入口：<http://localhost:8000/>。

| 情形 | 处理结果 |
| --- | --- |
| 更正/延期公告**明确写出新的投标截止时间** | 用新时间**替换**旧时间，状态为“有效” |
| 较晚公告**声明延期却未给出新时间** | 状态标为 **“待核实”**，不再显示/沿用旧截止时间 |
| 所有公告均未公布截止时间 | 状态为“未公布” |
| 只有原始招标公告 | 沿用原截止时间，状态为“有效” |

同一项目的全部公告（原公告、更正、延期）按发布时间升序保留，并附原文链接，便于回溯核对。

```

│   ├── Dockerfile
│   ├── requirements.txt
│   └── app/
│       ├── main.py             # 路由：延期核对、静默改写核查、页面代理
│       ├── crawler.py          # 列表页/下一页/详情页抓取与完整性标记
│       ├── parser.py           # 按字段标签解析详情
│       ├── content.py          # 字段表/正文可见文字提取与空白归一化
│       ├── baseline.py         # SQLite 基线与前后文字比较
│       ├── rewrite_check.py    # 抓取 + 基线比较的编排
│       ├── merger.py           # 按项目编号归并截止时间
│       ├── models.py
│       ├── utils.py
│       └── templates/
│           ├── index.html      # 招标延期核对 + 功能入口
│           └── rewrites.html   # 静默改写核查结果
├── example-site/               # 同结构本地示例站点（Python 标准库服务器）
│   ├── Dockerfile
│   ├── generate_site.py        # 生成原始版 A 与静默改写版 B
│   ├── serve.py                # 同一详情 URL 动态切换 A/B 版本
│   └── site/                   # 构建时生成（已加入 .gitignore）
└── tests/test_end_to_end.py    # 端到端测试
```

## 用 Docker Compose 启动

```bash
docker compose up --build
```

- 网页应用：<http://localhost:8000>
- 示例站点：<http://localhost:8080>
- 示例站切换控制台：<http://localhost:8080/control.html>

在网页输入框填入容器内示例站点地址：

```
http://example-site/list/page_1.html
```

### 演示静默改写

1. 打开 <http://localhost:8000/rewrites>，输入 `http://example-site/list/page_1.html`，
   点击“核查静默改写”——首次完整采集会建立 SQLite 基线；
2. 打开 <http://localhost:8080/control.html>，切换到 **B（静默改写后）**；
3. 再次点击“核查静默改写”：3 个**相同详情 URL**上的文字发生变化，页面展示变动前后的
   文字及来源链接，并以本次完整采集更新基线；
4. 切回 A 再核查，会看到文字反向变动。

版本 B 只改详情页内容，不新增更正公告，也不改变列表页和详情 URL，模拟真实网站
“直接改写原公告”的行为。

## 解析器的字段适配

详情页解析不绑定固定模板，按“字段标签 → 值”依次尝试：

1. 表格行（`th/td`，含一行两对字段）；
2. `dl/dt/dd` 定义列表；
3. `label` + 输入控件（`input/textarea/select`）；
4. 正文中的“标签：值”段落。

标签支持常见别名（如“招标项目编号/项目编码”“投标文件递交截止时间/开标时间”等），
标签缺失时再用正则兜底；识别不到项目编号的页面会被跳过并记为解析失败（本次采集不完整）。

## 安全与边界

- 仅跟随与入口**同站点**（协议 + 主机 + 端口一致）的“下一页”和详情链接，跨站链接跳过并记录；
- 只允许 `http(s)`，拒绝 `file://` 等协议；
- 上限：列表页 10 个、详情页 100 个、单请求超时 15 秒；
- `/view`、`/asset` 代理同样只转发 `http(s)` 目标。

## 本地测试（无需 Docker）

```bash
pip install -r webapp/requirements.txt
python example-site/generate_site.py
python -I tests/test_end_to_end.py
```

不带 Docker 手动运行示例站（默认监听 80，可用 `PORT` 覆盖）：

```bash
python example-site/serve.py
```

然后在另一个终端启动网页：

```bash
cd webapp
uvicorn app.main:app --host 0.0.0.0 --port 8000
```
